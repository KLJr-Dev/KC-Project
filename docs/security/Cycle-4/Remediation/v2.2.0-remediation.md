## Per-finding detail

### C4-F01 — Stored XSS (Notes render)

**v1.2.0 state:** Note detail HTML mode injects `note.body` with `dangerouslySetInnerHTML`. Markdown mode runs `unsafeMarkdownToHtml` (no HTML escape) into the same sink. Red proved `img onerror` alert; raw `<script>` often stripped/non-executing but sink remains.

**v2.2.0 intent:** Treat note body as **untrusted text**. Prefer escaped plain text or a vetted markdown renderer with HTML disabled. Remove SoftDev `unsafe-markdown` path from production UI.

**Verification:** Regression test creates note with `<img src=x onerror=…>` and asserts no executable sink (escaped text or sanitized empty).

### C4-F01b — Inline attachments

**v1.2.0 state:** SoftDev allows SVG/HTML attachments with inline-friendly disposition (XSS candy).

**v2.2.0 intent:** Restrict MIME; force download disposition for remaining types; reject scriptable types.

### C4-F02 — Secrets in privileged notes

**v1.2.0 state:** Seeded admin ops note holds F2 + `lab`/`labpass`/`:2222`.

**v2.2.0 intent:** Secure tip seeds must not teach live bastion passwords. Remove or replace with innocuous admin notes. Flag/SSH plants remain documentary on `ctf/v1.2.0` only.

### C4-F03 — SSH overlay

**v1.2.0 state:** Full-chain lab uses `docker-compose.ssh.yml`; prod alone must not publish `:2222` (already asserted).

**v2.2.0 intent:** Unchanged assert; README / secure-ready state clearly that **`v2.2.0` demos use prod (or TLS) without SSH**. Overlay retained for replaying frozen `v1.2.0` / teaching only.
