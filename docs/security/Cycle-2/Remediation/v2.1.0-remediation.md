## Reality check

Cycle-2 Criticals (**C2-F01…F03**) were **intentional CTF breaks** behind `CTF_MODE` + `docker-compose.ctf.yml` on `ctf/v1.1.0`. They do **not** exist on `main` / `v2.0.0`.

| Finding | On `ctf/v1.1.0` | On `main` (`v2.0.0`) today |
|---------|-----------------|----------------------------|
| C2-F01 IDOR | `assertCanRead` no-op when `CTF_MODE` | Ownership enforced |
| C2-F02 JWT role + HS256 | Trust JWT `role`; weak HS256 | `HasRoleGuard` loads DB role; **RS256** in prod |
| C2-F03 PG + loot password | `:5433` published; `DB_PASSWORD=` in seed file | PG **unpublished**; no CTF loot seeds |
| C2-F04 Cleartext HTTP | Day-to-day `:8080` | Same lab default; **TLS overlay already exists** |
| Headers / CSP / CORS | Present via nginx | Present (Cycle-1 M4/M8) |

**v2.1.0 is not a second full baseline rewrite.** It is:

1. **Regression-lock** the Cycle-2 attack chain on the secure stack.  
2. Close **ops residuals** (LAN TLS policy, least-priv DB, docs, stale comments).  
3. **Process fence** so next CTF cannot silently poison `main`.  
4. Sign **`v2.1.0`** as a secure, expandable fork point — every leftover weakness in Bucket A or B.

Do **not** “fix” vulns on `ctf/v1.1.0` — that box stays replayable.

## Per-finding detail

### C2-F01 — Horizontal IDOR on files (Critical)

**CTF state (v1.1.0):** With `CTF_MODE=true`, ownership checks no-op; any authenticated user can `GET` / download other users’ files (including flag files). See writeup §9 on `ctf/v1.1.0`.

**Secure state (v2.0.0 / this branch):** `assertCanRead` enforces owner or admin/moderator; delete similarly restricted.

**v2.1.0 delta:** Audit + regression e2e naming the Cycle-2 chain. No control rewrite. Confirm **no** `CTF_MODE` / CTF compose / CTF seeds on this branch.

**Files:** `backend/src/files/files.service.ts`, `files.controller.ts`.

**Verification:**

- e2e: `backend/test/idor.e2e-spec.ts` (plus Cycle-2 regression block in M2).
- curl (user B token, file owned by A):

```bash
curl -sS -w "\n%{http_code}\n" -H "Authorization: Bearer $TOKEN_B" \
  http://127.0.0.1:8080/api/files/<id-owned-by-A>
# expect 403
```

---

### C2-F02 — Weak HS256 secret + JWT role trusted (Critical)

**CTF state (v1.1.0):** HS256 with crackable lab secret; admin routes trust JWT `role` claim.

**Secure state (v2.0.0 / this branch):** `HasRoleGuard` loads `User.role` from DB by `sub`; JWT `role` is non-authoritative. Production requires RS256 (PEM mounts under `/run/secrets`).

**v2.1.0 delta:** Regression e2e for forged admin; confirm prod boot refuses HS256 fallback.

**Files:** `backend/src/auth/guards/has-role.guard.ts`, jwt-config / auth module, `infra/keys/jwt-*.pem`, compose key mounts.

**Verification:**

- e2e: `backend/test/admin.e2e-spec.ts` (forged admin → 403).
- Sign JWT with `role:admin` while DB role is `user` → `GET /api/admin/users` → **403**.

---

### C2-F03 — PostgreSQL published; credentials in loot (Critical)

**CTF state (v1.1.0):** Host port **5433** published; admin file embeds `DB_PASSWORD=…` for chain completion.

**Secure state (v2.0.0 / this branch):** Prod compose does **not** publish Postgres; backend reaches `postgres:5432` on the Docker network only. No CTF loot seeds on secure path. (E2e may use a separate publish overlay.)

**v2.1.0 delta:** Compose audit + host port closed check in M2. No loot lines in secure seeds.

**Files:** `infra/docker-compose.prod.yml`, seed migrations (absence of CTF plants).

**Verification:**

```bash
docker compose -f infra/docker-compose.prod.yml config
# no host binding for 5433
# optional: nc -zv 127.0.0.1 5433 → connection refused
```

---

### C2-F04 — Cleartext HTTP (Medium)

**CTF state (v1.1.0):** App on HTTP; Bearer + refresh cookie traverse LAN in cleartext (`Secure=false`).

**Secure state (v2.0.0 / this branch):** Day-to-day lab still HTTP `:8080` (accepted residual R-01). TLS profile already exists: `docker-compose.tls.yml` → `:8443`, HSTS, `COOKIE_SECURE=true`, `tls-smoke.sh`.

**v2.1.0 delta:** **Policy + docs** — loopback HTTP OK; LAN / recruiter secure demos **must** use TLS overlay. Tag requires `tls-smoke`. Do **not** make TLS the only day-to-day compose (R-04).

**Files:** `infra/docker-compose.tls.yml`, `infra/nginx-tls.conf`, cookie util, `infra/README.md`, gate doc.

**Verification:** `./infra/tls-smoke.sh` green before tag; README states LAN → TLS.

---

### C2-F05 — Global rate limit / 429 (Informational)

**CTF state (v1.1.0):** Aggressive enum hits global 429 — attacker friction only; does not fix IDOR.

**Secure state:** Nest throttler + nginx `limit_req` on `/api/auth/` remain.

**v2.1.0 delta:** Keep; document that throttles ≠ authorization.

**Files:** Nest throttler config, `infra/nginx.conf`.

**Verification:** None required beyond existing behavior.

---

### C2-F06 — Access token expiry vs refresh cookie (Informational)

**CTF state (v1.1.0):** ~15m Bearer expiry; stale shell `$TOKEN` yields 401, easy to misread as failed exploit.

**Secure state:** Same by design (short-lived access JWT + httpOnly refresh).

**v2.1.0 delta:** Short operator/docs note (auth-flow or infra README): refresh via cookie; re-login / silent refresh for SPA.

**Files:** `docs/architecture/auth-flow.md` and/or operator section in `infra/README.md`.

**Verification:** Doc exists and is linked from blue-team / gate.

---

### C2-F07 — Destructive DB capability (Informational / noted)

**CTF state (v1.1.0):** Superuser DB login enables DDL/DoS (RoE forbade execution).

**Secure state (v2.0.0 / this branch):** App still commonly connects as `postgres` (elevated). PG not on host, but least privilege incomplete.

**v2.1.0 delta:** **Must-close in Wave C (M3)** — not a silent residual.

**Design (implement in M3):**

1. **Migrator role** — elevated; runs TypeORM migrations only.  
2. **Runtime role `kc_app`** — DML on app tables only; no `DROP DATABASE` / role admin.  
3. Compose / `.env`: app `DB_USER=kc_app`; document in `infra/README` + `.env.example`.

**Acceptance:** App connection cannot `DROP DATABASE`; smoke/journey/e2e still green.

**Files:** `infra/docker-compose.prod.yml`, DB init/bootstrap SQL or migration bootstrap, `infra/.env.example`, `infra/README.md`.
