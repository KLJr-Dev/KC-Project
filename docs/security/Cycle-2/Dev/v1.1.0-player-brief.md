# KC-Project v1.1.0 — Player brief (no spoilers)

CTF-style lab built from the secure v2.0.0 parallel. Same product (files, sharing, roles, admin).  
**Not** a kitchen-sink vuln dump — expect a short chain and **OSCP-style proofs**.

## Target

```bash
docker compose -f infra/docker-compose.prod.yml -f infra/docker-compose.ctf.yml up -d --build
```

- App: `http://<target>:8080`
- Enumerate other ports yourself

## Rules of engagement

1. Flags are **32-character hexadecimal** strings (look like MD5).
2. A valid proof shows **who you are** at that tier **and** the flag contents (same idea as `whoami` + `cat local.txt` / `proof.txt` on OSCP).
3. Submitting a hash without identity context does not count.
4. Do not attack hosts outside the lab compose project.
5. No destructive wiping of the database volume unless the lab brief allows reset.

## Suggested tooling

nmap, directory fuzzing (gobuster/feroxbuster), Burp or curl, password spraying (hydra/ffuf), JWT inspection, `psql` when you have a reason.

## Out of scope (this release)

SSH/FTP shells are **not** part of v1.1.0. Stay on the web + DB attack surface.
