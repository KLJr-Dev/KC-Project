## Objective

Grey-box **web / API** assessment of the Northwind employee portal after the onboarding / HR release. Recover **four** graded proofs. Expect a **single-session AppSec** engagement (recon → authz flaws → workflow abuse → data leak) — **no** shell, AD, FTP, or infra pivot.

| ID | Theme |
|----|--------|
| F1 | Object-level access on onboarding cases |
| F2 | Identity / privilege across a service hop |
| F3 | File reach after workflow gate (export) |
| F4 | Monitoring / events trust boundary |

Flag format: `OS{` + 32 lowercase hex + `}`.

Moderator, admin, and Security Ops capabilities are **in scope to earn** through findings — not supplied at kickoff.

### Target (Kali → lab host)

UTM **Shared Network** (your setup) or VirtualBox **Host-Only** — subnets differ:

| Hypervisor | Kali (guest) | Target (Mac / Docker host) | Check |
|------------|--------------|----------------------------|--------|
| **UTM Shared** | e.g. `192.168.64.3/24` | **`192.168.64.1:8080`** | `ping 192.168.64.1` |
| VirtualBox Host-Only | e.g. `192.168.56.10/24` | `192.168.56.1:8080` | `ping 192.168.56.1` |

Reachability: `curl -sS http://<TARGET_IP>:8080/api/ping` → `200`

Do **not** use `192.168.56.1` on UTM Shared — that was VirtualBox-only; it will 100% packet loss.

## Rules of engagement

- **In scope:** Web UI and `/api/*` reachable through nginx; especially `/api/intake/*`; onboarding + export + events flows; header/body manipulation in Burp.
- **Out of scope:** DoS; unpublished ports (Postgres, internal Intake `:8000`); FTP/SSH/Cowrie; shell/PrivEsc; re-breaking Cycle-6/7/8 closed plants (Preview SSRF, Notes XSS, Ops LFI, Intake SQLi).
- Do not “fix” plants on this tip — Blue is **`v2.6.0`** after Red.
- Timebox honeypots — if a response says **services were alerted**, log it and move on.

## Progressive hints

<details>
<summary>Hint 1</summary>
HR / onboarding workflows often sit behind the Intake API prefix — the edge may be a **gateway/BFF**, not the Python service itself.
</details>

<details>
<summary>Hint 2</summary>
Object IDs that look sequential are worth walking.
</details>

<details>
<summary>Hint 3</summary>
When two teams share a hop, **identity headers** repay inspection.
</details>

<details>
<summary>Hint 4</summary>
Approvals that flip `pending` → `approved` are classic **race** territory.
</details>

<details>
<summary>Hint 5</summary>
Export endpoints that take a **filename** invite path tricks (`../`, encodings).
</details>

<details>
<summary>Hint 6</summary>
A bolted-on “security events” feed may log more than it should.
</details>

<details>
<summary>Hint 7</summary>
Some paths exist to burn time. If a response clearly says **services were alerted**, treat it as a tripwire and move on.
</details>
