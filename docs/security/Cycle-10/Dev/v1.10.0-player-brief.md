## Progressive hints (spoiler-light)

1. The edge landing is thin corporate chrome — **view source**; staff instructions are sometimes left as HTML comments off the main nav.  
2. Self-service register creates ordinary employees. **Document Ops** packet intake is a different access path.  
3. After a Document Ops session, partner/vendor packets go through a portal inbox — processing often sits **beside** the web tier, not on the published host.  
4. With a low-priv shell on the processor, look for user-readable proofs first; root material usually needs a **local PrivEsc**.  
5. After root on the processor, forgotten **data restores** and **ops mail** repay enumeration — cutover runbooks are classic.  
6. Department file shares and jump hosts continue the cutover story.  
7. Management bastions are rarely reachable from every subnet. Sticky notes on helpdesk desks are **unreliable**.

## Success criteria

Full compromise along one continuous chain: Document Ops session → processor foothold → root proof → ops intel → jump host → management crown. Three graded proofs (`local` / `proof` / `crown`) if present.
