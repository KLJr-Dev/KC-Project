## 1 — Client briefing (scenario)

**Northwind Traders** cut over an employee **Document Portal** and a segmented ops network. Leadership wants an external-style assessment of the published face and anything a determined outsider can reach after a foothold.

You are the Red team. Start **anonymous** against the published HTTPS edge. Treat the environment as a short consulting engagement: recon, exploit, escalate, pivot, prove crown access, write it up. Do not “fix” the tip mid-test — remediation is a separate Blue track.

Immersion note: the product face is Document Ops / partner packets. Legacy portal features from earlier cycles may still exist; they are **not** the graded Cycle-10 spine unless they feed it.

---

## 2 — Objective

Recover **three** graded proofs along **one continuous chain** (web → shell → PrivEsc → pivot → crown).

| ID | Theme (spoiler-light) |
|----|------------------------|
| local | Interactive low-priv foothold on the document-processing host |
| proof | Local privilege escalation on that same host |
| crown | Management-plane compromise reachable only after internal pivot |

**Flag format:** `OS{…}` (opaque).  
**Proof standard:** OSCP-style — interactive path where a shell/session is the intended proof. Do not treat “read the flag via an unintended shortcut” as graded success when the brief implies foothold → escalate → pivot.

Expect a **multi-session** engagement. Self-registration, sticky notes, unpublished decoys, and prior-cycle product surfaces exist to burn time. Material that works on one service often fails on the next.

### Success criteria (pass bar)

- [ ] Valid Document Ops–capable session earned without seeded moderator/admin shortcut (unless trainer-approved and disclosed)  
- [ ] Interactive foothold + `local`  
- [ ] PrivEsc + `proof`  
- [ ] Internal pivot completed (mail / share / jump story as required by the path)  
- [ ] `crown` from the intended management access path  
- [ ] Writeup + screenshots on `ctf/v1.10.0` covering recon → crown, including dead ends you hit

## 4 — Rules of engagement

### 4.1 Authorization

| Rule | Detail |
|------|--------|
| Authorized target | This Docker lab only: `prod` + `cycle10-lab` overlay at tip **`v1.10.0`** / **`ctf/v1.10.0`** |
| Start posture | Anonymous external against the given URL |
| Credentials | No gifted crown / bastion secrets. Earn Document Ops access yourself unless a trainer explicitly allows a Stage-0 shortcut |
| Intent | Full compromise for portfolio / training — not a production pen test of a real company |

### 4.2 In scope

- HTTPS Document Portal / Nest API on the published edge (`:443`)  
- Self-registration and any **discoverable** document-staff / access-request flows  
- Document packet upload / processing surfaces reachable after a Document Ops session  
- Reverse shells, listeners, and post-exploitation on compromised **lab** hosts  
- Local PrivEsc on those hosts  
- Credential reuse / spraying **inside the lab** with material you discovered  
- Pivot to internal lab hosts **only** via a valid foothold path that reaches them  
- Noise hosts and decoys for enumeration / timebox practice (document them; they are not graded skips)

### 4.3 Out of scope

- DoS / resource exhaustion against the lab host or compose stack  
- Attacking other students, shared cloud accounts, or anything outside this compose project  
- Real Northwind / Internet production systems  
- Re-breaking **closed** Cycle-6–9 Criticals (Preview/CSRF/Notes/Ops/Intake) as the Cycle-10 graded path  
- Real AD / Windows domains outside this lab  
- “Fixing” SoftDev plants mid-engagement (Blue = **`v2.10.0`**)  
- Publishing HostPorts SoftDev left unpublished, then attacking those ports as if they were the intended face  
- Wide LAN / Internet sweeps beyond the authorized lab target  

### 4.4 Allowed / expected techniques

| Allowed | Notes |
|---------|--------|
| Port / service enum of the published face | Expect HTTPS-only on the host |
| Web recon (dirs, source, JS, APIs) | View-source matters |
| Auth flows you can reach | Register, login, access requests if discovered |
| File upload / injection against in-scope surfaces | After Document Ops session |
| Reverse shells + tunnels | Lab hosts only |
| Password spraying with lab-discovered material | Timebox; don’t thrash the stack |
| PrivEsc (sudo, misconfigs, GTFOBins-class) | On owned lab hosts |
| Pivoting / SOCKS / SSH jumps | Once network path exists from foothold |

### 4.5 Forbidden / discouraged

| Forbidden | Why |
|-----------|-----|
| Seeded `mod@` / `admin@` as graded Stage-0 | Skips Document Ops discovery (see §5) |
| Intentional DoS / fork bombs / disk fill | Breaks the shared lab |
| Patching plants to “win faster” | Corrupts the tip |
| Exfiltrating writeup/flags into `main` | Evidence stays on `ctf/v1.10.0` |
| Treating examiner output as your writeup | Examiner ≠ engagement narrative |

### 4.6 Evidence & reporting rules

- Capture screenshots / command output that prove each stage (home → session → shell → flags → crown).  
- Prefer reproducible commands in the writeup over lore.  
- Document false paths you burned time on.  
- Freeze the writeup on **`ctf/v1.10.0`** when crown is proven.  
- Template: [../PenTest/v1.10.0-writeup.md](../PenTest/v1.10.0-writeup.md) · screenshots: [../PenTest/screenshots/](../PenTest/screenshots/).

### 4.7 Emergency stop

If the compose stack is wedged (OOM, hung builds, host disk full): stop offensive work, `down --remove-orphans -v`, bring the lab back clean, resume. Do not “fix” application plants to recover the box.

## 7 — Progressive hints

<details>
<summary>Hint 1 — face</summary>
The published face is thin corporate chrome. View-source and off-nav staff crumbs often beat guessing admin panels.
</details>

<details>
<summary>Hint 2 — identity</summary>
Self-service register creates ordinary employees. Document Ops packet intake is a different access path than “I made an account.”
</details>

<details>
<summary>Hint 3 — processing</summary>
Partner/vendor packets go through a portal inbox. Processing often sits <em>beside</em> the web tier — not on a second HostPort you can nmap from Kali.
</details>

<details>
<summary>Hint 4 — foothold proofs</summary>
With a low-priv shell on the processor, grab user-readable proofs first. Root material usually needs a local PrivEsc (sudo / GTFOBins territory).
</details>

<details>
<summary>Hint 5 — post-root enum</summary>
After root on the processor, forgotten data restores and ops mail repay enumeration. Cutover runbooks are classic.
</details>

<details>
<summary>Hint 6 — corp pivot</summary>
Department file shares and jump hosts continue the cutover story. Sticky notes on helpdesk desks are unreliable.
</details>

<details>
<summary>Hint 7 — crown (almost spoiler)</summary>
Management bastions are rarely reachable from every subnet. The secret that opens the final door often required root earlier — and the jump path is as important as the password.
</details>
