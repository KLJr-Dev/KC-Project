## Objective

You are assessing **Northwind Traders’ Document Portal** and the surrounding enterprise network lab. Recover **three** graded proofs along one continuous chain (web → shell → PrivEsc → pivot → crown).

| ID | Theme |
|----|--------|
| local | Interactive low-priv foothold on the document-processing host |
| proof | Local privilege escalation on that host |
| crown | Management-plane compromise reachable only after pivot |

Flag format: `OS{…}` (opaque string). Treat proofs as **OSCP-style**: interactive path where a shell is the intended proof — not “download the flag without the graded foothold.”

Expect a **multi-session** engagement. Self-registration, sticky notes, unpublished decoys, and prior-cycle product surfaces exist to burn time. Cracked or found material for one service often does **not** unlock the next.

## Rules of engagement

### Authorization

- Authorized target: this Docker lab tip (`prod` + `cycle10-lab` overlay) checked out as **`v1.10.0`** / **`ctf/v1.10.0`**.  
- Engagement style: HTB / OSCP-style **full compromise** — anonymous external start → web chain → reverse shell → PrivEsc → internal pivot → crown.  
- No gifted crown / bastion credentials. Earn Document Ops access yourself unless your trainer explicitly allows a Stage-0 shortcut.

### In scope

- HTTPS Document Portal / Nest API on the published edge (`:443`)  
- Self-registration and any **discoverable** document-staff access flows  
- Document packet / processing surfaces reachable after a Document Ops session  
- Pivot to internal lab hosts **only** once you have a valid foothold path that reaches them  
- Local PrivEsc on compromised lab hosts  
- Credential reuse / spraying **inside the lab** with material you discovered  
- Noise hosts and decoys **for enumeration/timebox practice** (document them; they are not graded skips)

### Out of scope

- DoS / resource exhaustion against the lab host or compose stack  
- Attacking other students, shared infra outside this compose project, or real Northwind / production systems  
- Re-breaking **closed** Cycle-6–9 Criticals (Preview/CSRF/Notes/Ops/Intake) as the Cycle-10 graded path  
- Real AD / Windows domains outside this lab  
- “Fixing” plants on this tip — Blue is **`v2.10.0`** after Red freeze  
- Publishing or attacking HostPorts that SoftDev intentionally left unpublished (if you `docker publish` them yourself, you left the intended RoE)

### Demo accounts (hard rule for graded play)

Seeded `user@` / `mod@` / `admin@` exist for the **legacy product UI**. For a graded Cycle-10 engagement:

- Do **not** start as seeded `mod@` / `admin@` to skip Document Ops discovery.  
- Open register → ordinary employee is fine (and often a dead end on Document Ops).  
- Trainers may allow demo moderator as a timebox shortcut — mark it honestly in the writeup if used.

### Conduct

- Timebox rabbit holes; document false paths.  
- Prefer interactive, reproducible steps in the writeup.  
- Do not merge CTF evidence into `main`; freeze writeup on **`ctf/v1.10.0`**.

## Progressive hints

<details>
<summary>Hint 1</summary>
The published face is thin corporate chrome. View-source and off-nav staff crumbs often beat guessing admin panels.
</details>

<details>
<summary>Hint 2</summary>
Self-service register creates ordinary employees. Document Ops packet intake is a different access path than “I made an account.”
</details>

<details>
<summary>Hint 3</summary>
Partner/vendor packets go through a portal inbox. Processing often sits <em>beside</em> the web tier — not on the host you can nmap from Kali.
</details>

<details>
<summary>Hint 4</summary>
With a low-priv shell on the processor, grab user-readable proofs first. Root material usually needs a local PrivEsc (sudo / GTFOBins territory).
</details>

<details>
<summary>Hint 5</summary>
After root on the processor, forgotten data restores and ops mail repay enumeration. Cutover runbooks are classic.
</details>

<details>
<summary>Hint 6</summary>
Department file shares and jump hosts continue the cutover story. Sticky notes on helpdesk desks are unreliable.
</details>

<details>
<summary>Hint 7 (almost spoiler)</summary>
Management bastions are rarely reachable from every subnet. The secret that opens the final door often required root earlier — and the jump path is as important as the password.
</details>
